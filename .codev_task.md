## 2. Chi tiết các yêu cầu kỹ thuật

### 2.1. Cập nhật `src/config/firestore-mock.ts`
Mở rộng `mockFirestore` để hỗ trợ:
- `runTransaction(updateFunction)` thực thi hàm transaction callback in-memory với transaction object hỗ trợ `get`, `set`, `update`, `delete`.
- Hỗ trợ `admin.firestore.FieldValue.increment(n)`.
- Đảm bảo các query `where`, `orderBy`, `limit` hoạt động chuẩn xác với các collection mới:
  - `channels`
  - `channel_members`
  - `pairing_sessions`
  - `pairing_requests`
  - `channel_key_envelopes`
  - `messages` (v2)

### 2.2. Schema Validation (Zod) cho v2
Tạo file `src/schemas/v2/index.ts` (hoặc tương đương) xác thực:
1. `POST /api/v2/devices/register`: `public_key` (Base64 string 32-byte X25519), `device_name` (optional/trimmed, max 100), `platform` (optional, enum: 'android'|'ios'|'web'|'unknown'). Trả về `device_token`, `device_id`. Idempotent nếu gọi lại cùng public_key hoặc device_id.
2. `PUT /api/v2/devices/name`: `device_name` (string 1..100). Đổi tên thiết bị caller, fan-out sang mọi `channel_members` ACTIVE và `pairing_requests` PENDING của thiết bị đó.
3. `POST /api/v2/channels`: `channel_name` (string 1..100). Caller trở thành Owner, tạo doc `channels` với `current_epoch = 1`, `sequence_counter = 0`, tự động tạo `channel_members` ACTIVE cho Owner tại epoch 1.
4. `GET /api/v2/channels`: Trả về danh sách channels mà caller là member ACTIVE (gồm cả Owner và Member) kèm role ('owner'|'member').
5. `GET /api/v2/channels/detail`: Query: `channel_id`. Chỉ member ACTIVE mới xem được (ngược lại 403 REVOKED hoặc 404 NOT_FOUND). Trả về channel metadata, member count, current_epoch.
6. `GET /api/v2/channels/members`: Query: `channel_id`. Trả về danh sách members ACTIVE (device_id, device_name, role, joined_at, joined_epoch).
7. `POST /api/v2/channels/sessions`: Body: `channel_id`. Chỉ Owner mới được gọi. Tạo pairing session TTL 10 phút, trả về `session_id`, `token` (CSPRNG 128-bit hex), `qr_data` (`smsnavigator://join?ch=...&token=...&srv=...`).
8. `POST /api/v2/pairing/requests`: Body: `token`, `encrypted_device_name` (optional). Member B gửi yêu cầu kết nối bằng token. Thực hiện Transaction T1: kiểm tra session UNUSED & chưa hết hạn -> chuyển thành CLAIMED. Tạo doc `pairing_requests` với trạng thái `PENDING`.
9. `GET /api/v2/channels/requests`: Query: `channel_id`, `status` (mặc định PENDING). Chỉ Owner mới xem được danh sách request.
10. `POST /api/v2/pairing/requests/approve`: Body: `channel_id`, `request_id`, `new_epoch` (number = current_epoch + 1), `envelopes` (mảng `{ device_id, encrypted_key, iv, sender_ephemeral_pubkey }`).
    Thực hiện Transaction T2:
    - Kiểm tra caller là Owner của channel.
    - Kiểm tra `request_id` đang PENDING.
    - Tăng `current_epoch` lên `new_epoch`.
    - Thêm requester vào `channel_members` trạng thái ACTIVE (`joined_epoch = new_epoch`).
    - Lưu các `channel_key_envelopes` cho epoch mới (`{channelId}__{deviceId}__{new_epoch}`).
    - Cập nhật request thành APPROVED.
    - Giả lập gửi FCM chuông `CHANNEL_KEY_ROTATED` / `REQUEST_APPROVED` qua `fcmService`.
11. `POST /api/v2/pairing/requests/reject`: Body: `channel_id`, `request_id`. Chỉ Owner gọi. Cập nhật request thành `REJECTED`.
12. `POST /api/v2/pairing/requests/cancel`: Body: `channel_id`, `request_id`. Chỉ requester gọi. Cập nhật request thành `CANCELLED`.
13. `GET /api/v2/channels/key-envelope`: Query: `channel_id`, `epoch` (number). Caller phải là member ACTIVE. Trả về doc trong `channel_key_envelopes` cho `{channel_id}__{caller_device_id}__{epoch}`.
14. `POST /api/v2/channels/messages`: Body: `channel_id`, `request_epoch`, `ciphertext`, `iv`, `sender_ephemeral_pubkey`, `sent_at`, `expires_at`.
    - Chỉ Owner được gửi tin.
    - Transaction T3: kiểm tra `request_epoch === current_epoch` (nếu khác trả 409 EPOCH_OUTDATED).
    - Tăng `sequence_counter` của channel lên 1 và gán vào message.
    - Lưu message vào `messages`.
    - FCM chuông tới các active members.
15. `GET /api/v2/messages`: Query: `date` (YYYY-MM-DD), `tz_offset` (phút).
    - Channel-agnostic: Lấy tất cả tin nhắn trong ngày chỉ định của MỌI kênh mà caller hiện đang là thành viên ACTIVE.
    - Bỏ qua các kênh mà caller đã bị REVOKED.
    - Sắp xếp theo timestamp/sequence.
16. `POST /api/v2/channels/revoke`: Body: `channel_id`, `target_device_ids` (mảng string), `new_epoch`, `envelopes`.
    - Chỉ Owner gọi.
    - Transaction T4: cập nhật các target_device_ids thành REVOKED trong `channel_members`.
    - Tăng `current_epoch` lên `new_epoch`.
    - Lưu envelopes cho các members còn lại.
    - FCM REVOKED tới các revoked devices.

### 2.3. Quy ước chung về Routing & Error Handling
- Tất cả endpoints v2 nằm dưới prefix `/api/v2`.
- CẤM path parameters cho v2 theo Spec §1 (Chỉ path tĩnh: GET dùng query, POST/PUT dùng JSON body).
- Xác thực dùng Bearer token `Authorization: Bearer <device_token>` (dùng lại auth middleware hiện có).
- Trả về đúng format `{ success: true, ... }` hoặc `{ success: false, error: "<CODE>", message: "..." }`.

### 2.4. Tests
Tạo file `tests/api-v2.test.ts`:
- Viết test suite hoàn chỉnh bao phủ tất cả 16 endpoints trên.
- Test kịch bản E2E hoàn chỉnh:
  1. Register Owner (A) và Member (B, C) với public keys.
  2. Owner tạo channel.
  3. Owner tạo session QR.
  4. Member B claim QR -> tạo request PENDING.
  5. Owner approve request -> epoch tăng lên 2, cấp envelope cho A và B.
  6. Member B lấy key-envelope epoch 2 thành công.
  7. Owner gửi encrypted message ở epoch 2 -> nhận sequence_number = 1.
  8. Member B fetch messages theo ngày -> thấy message.
  9. Owner revoke C (hoặc B) -> chuyển thành REVOKED, epoch tăng lên 3.
  10. Member bị revoke không còn lấy được messages hay gọi channel API (403 REVOKED).
- Chạy `npm test` để kiểm tra. Toàn bộ tests v1 (78 tests) và tests v2 phải pass 100%.
