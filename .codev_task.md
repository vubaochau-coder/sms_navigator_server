# TASK: Implement Device-bound Authentication, Pair Authorization & Blind Relay

## 1. Mục tiêu
Nâng cấp `sms_navigator_server` từ mô hình đơn giản sang kiến trúc bảo mật cấp cao:
- **Device-bound Authentication:** Quản lý thiết bị bằng CSPRNG token (chỉ lưu SHA-256 hash của token).
- **Pair Authorization & Ownership:** Chỉ thiết bị tạo Pair (Device A) mới có quyền gửi OTP vào Pair đó. Thiết bị lạ (Device C) sẽ bị 403 Forbidden.
- **Pairing Integrity:** Mã 6 số lưu dưới dạng SHA-256 hash, TTL 10 phút, chỉ dùng 1 lần (one-time use), giới hạn 5 lần đoán sai, chặn tự ghép với chính mình.
- **Blind Relay & Message Deduplication:** Chuyển tiếp OTP nguyên vẹn không giải mã, kèm `message_id` deduplication trong 10 phút.

## 2. Phạm vi can thiệp (Target Files)
- Sửa/Tạo mới các file trong `src/` và `tests/`:
  - `src/types/index.ts`: Bổ sung kiểu `DeviceEntity`, `PairEntity`, DTOs cho Device & Pair.
  - `src/services/device.service.ts`: Tạo mới quản lý thiết bị, sinh token CSPRNG `crypto.randomBytes(32).toString('hex')`, lưu `token_hash = sha256(token)`.
  - `src/services/session.service.ts`: Cập nhật lưu PairEntity có `sender_device_id`, `receiver_device_id`, `pairing_code_hash`, `pairing_code_expires_at`, `pairing_attempts`. Thêm cache `processedMessageIds: Set<string>` để deduplicate.
  - `src/middlewares/auth.middleware.ts`: Tạo mới middleware trích xuất `Authorization: Bearer <token>`, hash token bằng SHA-256, tìm device trong `deviceService`, gán vào `req.device`. Nếu không hợp lệ trả về 401 Unauthorized.
  - `src/controllers/device.controller.ts` & `src/routes/device.routes.ts`: `POST /api/v1/devices/register` (trả về raw token), `PUT /api/v1/devices/fcm-token` (cập nhật FCM token của receiver, cần auth).
  - `src/controllers/pair.controller.ts` & `src/routes/pair.routes.ts`:
    - `POST /api/v1/pair/init` (cần auth Device A): Sinh mã 6 số ngẫu nhiên, lưu hash vào pair, trả về pair_id & mã 6 số.
    - `POST /api/v1/pair/confirm` (cần auth Device B): Kiểm tra code hash, attempts <= 5, device_B != device_A, bind B vào pair, xóa pairing_code_hash.
    - `GET /api/v1/pair/status/:pairId`: Yêu cầu auth, chỉ A hoặc B của pair mới được xem (nếu Device C xem -> 403 Forbidden).
    - `DELETE /api/v1/pair/:pairId`: Yêu cầu auth, chỉ A hoặc B mới được revoke (nếu Device C -> 403 Forbidden).
  - `src/controllers/relay.controller.ts` & `src/routes/relay.routes.ts`:
    - `POST /api/v1/relay` (và `/api/v1/relay/otp`): Yêu cầu auth. Kiểm tra `req.device.device_id === pair.sender_device_id` (nếu sai -> 403 Forbidden). Kiểm tra deduplication `message_id` (nếu trùng -> 200 duplicate ignored). Chuyển tiếp payload vào FCM High-Priority Data message.
  - `src/routes/api.routes.ts`: Thêm `deviceRoutes` vào router tổng (`/devices`).
  - `src/app.ts`: Đảm bảo tích hợp đầy đủ routes mới.
  - `tests/api.test.ts`: Cập nhật và bổ sung toàn diện test suites cho tất cả các kịch bản trên.
- TUYỆT ĐỐI KHÔNG sửa các file ngoài dự án `sms_navigator_server/`.

## 3. Ràng buộc kỹ thuật chi tiết
1. **Hash Token & Code:**
   - Dùng `crypto.createHash('sha256').update(value).digest('hex')`.
   - Tuyệt đối không lưu plaintext token hoặc plaintext pairing code trong bộ nhớ/DB.
2. **Authorization (Ownership Check):**
   - Phân biệt rành mạch giữa 401 (Sai/Thiếu Token) và 403 (Token đúng nhưng không có quyền trên pair_id được yêu cầu).
3. **TypeScript Build Sạch:**
   - Đảm bảo `npm run build` không có bất kỳ lỗi TypeScript nào (`noImplicitAny`, type mismatch).
   - Mở rộng kiểu Express Request:
     ```typescript
     declare global {
       namespace Express {
         interface Request {
           device?: DeviceEntity;
         }
       }
     }
     ```
